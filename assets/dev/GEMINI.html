1. Project Purpose & Features

The CAT Scan Demonstration Tool is an interactive, educational Flutter application (Web and Android) illustrating how Computed Axial Tomography (CAT / CT scans) and the Radon Transform work.

The project is adapted from an original 1998/2006 Java applet by Fred Gylys- Colwell (gchouse.org). It explains:

  1. How 1D X-ray projections of an object at different angles form a 2D dataset called a sinogram (g(r,θ)g(r, \theta)).

  2. The geometric duality between points in object space and sinusoidal curves in sinogram space.

  3. How backprojection of unfiltered data produces a blurry reconstruction.

  4. How filtering projections with a ramp/edge filter (Frank Natterer’s discrete filter kernel wbw_b) sharpens the data so that backprojection yields the exact interior attenuation values.

Key Features

  • Dual Synchronized Viewports:

    • Object Space: Interactive 2D coordinate plane showing the object/phantom, active X-ray lines, and probe points.

    • Sinogram / Radon Space: 2D parameter plane (r,θ)(r, \theta) displaying attenuation values as an interactive heatmap, with probe cursors and sinusoidal curves.

  • 1D Profile & Backprojection Graph:

    • Live cross-sections of g(r,θ)g(r, \theta) along chosen angles θ\theta, radial offsets rr, or sinusoidal point trajectories.

    • Real-time calculation and display of the backprojection integral ∫02πg(xcos⁡θ+ysin⁡θ,θ)dθ\int_0^{2\pi} g(x\cos\theta + y\sin\theta, \theta) \, d\theta.

  • Guided 6-Stage Narrative: Step-by-step presentation following the original talk structure with rich narrative cards, Previous/Next navigation, and keyboard shortcuts.

  • Customizable Settings: Persistent theme (Dark / Light), colormaps (Classic Java purple-red-yellow, Viridis, Grayscale), grid sampling resolution (P×QP \times Q), and coordinate guides.

  • No File/Drive Storage: The app is an explanatory tool; file saving and Google Drive integration are omitted.

3. Mathematical Reference & Coordinate Conventions

3.1 Object Coordinates

  • The object space is normalized to [−1,1]×[−1,1][-1, 1] \times [-1, 1].

  • Origin (0,0)(0, 0) is at the center of the viewport.

  • Standard Cartesian coordinates: +x+x points right, +y+y points up (unlike screen pixel coordinates where +y+y points down).

3.2 Sinogram Coordinates

  • Angle θ∈[0,2π)\theta \in [0, 2\pi) discretized into 2P2P samples: θj=πj/P\theta_j = \pi j / P, for j∈{0,…,2P−1}j \in \{0, \dots, 2P - 1\}. Default P=50P = 50.

  • Radial distance r∈[−1,1]r \in [-1, 1] discretized into 2Q2Q samples: ri=(i−Q)/Q=h⋅i−1.0r_i = (i - Q)/Q = h \cdot i - 1.0, with step h=1/Qh = 1/Q. Default Q=50Q = 50.

  • Line equation: xcos⁡θ+ysin⁡θ=rx \cos\theta + y \sin\theta = r.

3.3 Phantom Line Integral

For a circular phantom disk with radius rpr_p, center (x0,y0)(x_0, y_0), and uniform density 11:

sc(θ)=x0cos⁡θ+y0sin⁡θs_c(\theta) = x_0 \cos\theta + y_0 \sin\theta

Δs=r−sc(θ)\Delta s = r - s_c(\theta)

ψ(Δs)={2rp2−(Δs)2if |Δs|<rp0otherwise\psi(\Delta s) = \begin{cases} 2\sqrt{r_p^2 - (\Delta s)^2} & \text{if } |\Delta s| < r_p \\ 0 & \text{otherwise} \end{cases}

3.4 Ramp Filter Kernel (Frank Natterer)

Discrete filter kernel for bandwidth b=πQb = \pi Q:

wb(l)=b2π4(1−4l2)(l∈ℤ)w_b(l) = \frac{b^2}{\pi^4 (1 - 4 l^2)} \quad (l \in \mathbb{Z})

Filtered sinogram:

(wb*g)(r,θ)=h∑l=−LLg(r−lh,θ)wb(l)(w_b * g)(r, \theta) = h \sum_{l = -L}^{L} g(r - l h, \theta) \, w_b(l)

4. Development Workflows & Local Commands

4.1 Running the App Locally

  • Local development server (Chrome):

    ./run-local-server.sh

Uses port 5515 on host raven and port 5006 on remote hosts.

  • Local release build test:

    ./run-local-release.sh

4.2 Building Assets & Docs

  • Rebuild documentation and icons:

    make ASSETS

  • Run automated tests:

    make test
# or: flutter test

  • Analyze Dart code:

    flutter analyze

  • Increment build version:

    ./roll_build_number.sh            # Increments build number (e.g. +1)
./roll_build_number.sh --release  # Increments release version (e.g. 1.0.1+0)

5. Engineering Guidelines & Quality Standards

  1. Precision & Documentation Integrity: Preserve comments, docstrings, and mathematical notations when modifying or extending files.

  2. Analysis Hygiene: Always keep flutter analyze clean (0 errors, 0 warnings).

  3. Responsive Custom Painting: Use CustomPainter efficiently. Precompute trigonometric lookup tables (sin\sin, cos\cos) and cache rasterized heatmaps so dragging the phantom or probe remains smooth at 60 FPS.

  4. File Links: When discussing code, reference file paths with standard clickable markdown links (e.g., [RadonEngine](lib/models/radon_engine.dart)).
